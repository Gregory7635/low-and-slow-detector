# Этап 1. Анализ предметной области и требования

## 1.1. Предметная область

Интернет-магазин (Apache, формат журнала `combined`) получает трафик от людей,
легитимных поисковых роботов и ботов-парсеров. Простые боты легко отсечь по
частоте запросов (rate limit). **Low-and-slow боты** специально держат
маленькую интенсивность — один запрос в десятки секунд или минут, — чтобы не
превышать пороги WAF и fail2ban. Они распределяют нагрузку по многим IP
(часто одной подсети), подделывают User-Agent поисковиков или браузеров
и копируют каталог, цены, остатки.

Признаки, по которым их всё же можно отличить от людей:

| Признак | Человек | Low-and-slow бот |
|---|---|---|
| Интервалы между визитами | нерегулярные | почти равные (таймер в скрипте) |
| Загрузка статики (картинки, CSS, JS) | вместе со страницей | часто отсутствует |
| User-Agent | реальный, согласованный | подделан, противоречив, «поисковик» без DNS |
| Распределение по IP | один IP — один посетитель | много IP одной подсети в одно время |
| Набор страниц | навигация, корзина | однотипный обход карточек/категорий |
| Referer | есть внутренний | пустой или одинаковый |

**Цель проекта** — программная система, которая по журналу Apache находит
IP-адреса low-and-slow ботов, объясняя причину, и даёт числовую оценку
аномальности каждого IP с помощью методов машинного обучения (в том числе
нейронной сети).

## 1.2. Обзор аналогов

| Критерий | fail2ban | CrowdSec | Cloudflare Bot Management | GoAccess | **Разрабатываемая система** |
|---|---|---|---|---|---|
| Работа по журналам Apache | да | да | нет (прокси) | да | да |
| Поиск медленных ботов | нет (только пороги частоты) | частично (сценарии) | да | нет | да |
| Проверка поисковиков по DNS | нет | частично | да | нет | да |
| Проверка правдоподобия User-Agent | нет | нет | да | нет | да |
| ML / нейросеть | нет | нет | да (закрытая) | нет | да (Isolation Forest, автоэнкодер) |
| Объяснение причины | регулярка | сценарий | балл | — | правило + вклад признаков |
| Стоимость | бесплатно | freemium | от $200/мес (Enterprise) | бесплатно | бесплатно |
| Работа офлайн, без передачи данных | да | да | нет | да | да |

Вывод: открытые инструменты ловят только «быстрых» ботов по порогам, а
коммерческие решения требуют проксирования всего трафика через сторонний
сервис. Ниша — офлайн-анализ журналов с объяснимыми правилами и ML-оценкой.

## 1.3. Функциональные требования

| № | Требование |
|---|---|
| ФТ-1 | Разбор журнала Apache в формате combined (IP, время, метод, путь, статус, размер, Referer, User-Agent), подсчёт пропущенных строк |
| ФТ-2 | Проверка заявленных поисковых роботов (Google, Yandex, Bing) через reverse + forward DNS, кэширование результатов |
| ФТ-3 | Выявление невозможных и противоречивых User-Agent (несуществующие версии, несовпадение ОС и браузера, средства автоматизации) |
| ФТ-4 | Выявление аномально равномерных интервалов между визитами (коэффициент вариации) |
| ФТ-5 | Выявление групп IP одной подсети, активных в одном временном окне |
| ФТ-6 | Выявление смены браузера/ОС на одном IP |
| ФТ-7 | Извлечение поведенческих признаков для каждого IP (не менее 15) |
| ФТ-8 | Обучение моделей поиска аномалий (Isolation Forest и нейросетевой автоэнкодер), сохранение и загрузка моделей |
| ФТ-9 | Получение оценки аномальности для каждого IP и итогового решения (правила + модель) |
| ФТ-10 | Генерация синтетических low-and-slow ботов для оценки качества с известной разметкой |
| ФТ-11 | Расчёт метрик (Precision, Recall, F1, ROC-AUC), матрицы ошибок и графиков |
| ФТ-12 | Выгрузка результатов в TXT и JSON |
| ФТ-13 | REST API: загрузка журнала, запуск анализа, получение результатов |
| ФТ-14 | Веб-страница: загрузка файла, таблица подозрительных IP, фильтры, графики |
| ФТ-15 | Белый список подсетей (CIDR), исключаемых из проверки |
| ФТ-16 | Сохранение истории анализов: повторное открытие результата, удаление, история решений по одному IP |

## 1.4. Нефункциональные требования

| № | Требование |
|---|---|
| НФТ-1 | Производительность: журнал 400 тыс. строк обрабатывается не дольше 60 с без учёта DNS (на ПК уровня Core i5 / 16 ГБ) |
| НФТ-2 | Точность: на тестовой выборке с синтетическими ботами F1 ≥ 0,85, Precision ≥ 0,9 итогового решения |
| НФТ-3 | Объяснимость: для каждого подозрительного IP указываются сработавшие правила и/или признаки с наибольшим отклонением |
| НФТ-4 | Воспроизводимость: фиксированный `random_state`, кэш DNS, сохранённые модели |
| НФТ-5 | Конфиденциальность: данные не покидают сервер; в репозиторий попадает только обезличенный пример журнала |
| НФТ-6 | Переносимость: Python 3.10+, Windows и Linux, зависимости в `requirements.txt` |
| НФТ-7 | Качество кода: PEP 8, модульная структура, покрытие unit-тестами ключевых модулей |

## 1.5. Варианты использования

Актёры: **администратор сайта**, **аналитик безопасности**, **внешняя система** (по API).
UML-диаграмма вариантов использования — [docs/uml/use_case.puml](uml/use_case.puml).

1. **Проанализировать журнал.** Администратор загружает `access.log`,
   система выдаёт список подозрительных IP с причинами.
2. **Обучить модель на своём трафике.** Аналитик запускает обучение на
   журнале «обычного» дня; модели сохраняются в `artifacts/`.
3. **Оценить качество детектора.** Аналитик запускает оценку: в журнал
   внедряются синтетические боты, считаются метрики и строятся графики.
4. **Настроить пороги.** Аналитик меняет окно подсети, порог CV,
   процентиль аномальности, белый список.
5. **Получить результат по API.** Внешняя система отправляет журнал на
   `POST /api/analyze` и получает JSON для блокировки IP на фаерволе.
6. **Вернуться к прошлому анализу.** Администратор открывает результат из
   истории или по ссылке и смотрит, как менялось решение по IP.

User stories:

- *Как администратор*, я хочу видеть, почему IP признан ботом, чтобы не
  заблокировать покупателя.
- *Как аналитик*, я хочу оценку аномальности от модели, чтобы находить
  ботов, которые не попадают ни под одно правило.
- *Как разработчик интеграции*, я хочу JSON-API, чтобы автоматически
  передавать список IP в ipset / Cloudflare.

## 1.6. Краткое техническое задание

- **Наименование:** «Детектор low-and-slow ботов по журналам Apache».
- **Назначение:** офлайн-выявление медленных ботов-парсеров.
- **Входные данные:** журнал Apache combined (текст, UTF-8).
- **Выходные данные:** список IP с причинами, оценками и итоговым решением (TXT, JSON, веб-таблица).
- **Состав:** модуль разбора, модуль правил, модуль признаков, ML-модуль, модуль оценки, хранилище истории, REST API, веб-интерфейс, CLI.
- **Стек:** Python 3.11, pandas, numpy, scikit-learn, PyTorch, FastAPI, Pydantic, SQLite, matplotlib, pytest.
- **Требования к качеству:** НФТ-1 … НФТ-7.
- **Порядок приёмки:** прохождение unit-тестов, метрики на тестовой выборке, демонстрация API и веб-страницы.
